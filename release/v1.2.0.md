# Catalyst Narrative Risk v1.2.0

## Claims, Sources, and Evidence Ledger

v1.2.0 turns the canonical method record into a traceable evidence system. Source-related risk inputs no longer need to exist as unexplained dropdown values: they can be derived from explicit claims, source records, evidence excerpts, and reviewable relationships.

### Canonical evidence ledger

The record now contains an `evidence_ledger` layer with:

- One primary claim plus optional supporting and contextual claims
- Source metadata, identifiers, provenance, independence groups, duplicate links, directness, and freshness
- Evidence excerpts, locators, capture times, and SHA-256 excerpt digests
- `support`, `qualify`, `contradict`, `contextualize`, and `unresolved` relationships
- Per-claim and overall coverage summaries
- Harvard-style source-list entries
- Ledger-derived source type, evidence strength, and source count

Every claim, source, evidence item, and relationship receives a deterministic canonical identifier when one is not supplied.

### Method behavior

When evidence relationships are linked to the primary claim, the method derives:

- `source_type` from the lowest-risk linked positive source class
- `source_count` from unique linked sources
- `evidence_strength` from the strongest positive relationship, with transparent downgrades for insufficient independence and contradiction

Manually supplied source values may match the derived values, but contradictory values are rejected.

### Provenance and integrations

The release adds first-party import contracts for:

- Knowledge Library document records
- Catalyst Data dataset records

Both adapters preserve the originating object identifier, import method, access time, and content hash when supplied.

### Exports and migration

- Canonical record JSON
- Markdown review brief
- Harvard-style bibliography
- Evidence-ledger JSON, Markdown, and CSV
- Deterministic v1.0.1 and v1.1.0 migration
- Exact verification of method, input, ledger, and record-payload hashes

Migration never invents item-level sources or evidence. Legacy scalar assessments are retained with explicit migration warnings until reviewers populate the ledger.

### Runtime parity

Python and browser JavaScript share the same generated method asset and fixture matrix. The release gate requires matching normalized inputs, evidence ledgers, calculations, interpretations, complete records, and SHA-256 digests.

### Methodological boundary

The ledger records how evidence relates to claims. It does not prove a claim, infer intent, or authorize publication. Human reviewers remain responsible for evidence interpretation and final disposition.
